Explain it to someone who has never seen your system.

greenhorn is a Claude Code plugin that rewrites technical text for a reader who is new to your system.

/plugin marketplace add gagoar/gago-plugins
/plugin install greenhorn@gago-plugins

A worked example

This Before and After pair is an illustration written for the README. It is not from a real pull request.

Before

Fixes the Photon regression by backing out the delta-sync change. The reconciler now short-circuits on a stale ETag and the rehydration path no longer double-fires the capture hook.

After

Images sometimes showed twice in the viewer. This change stops that.

For example, a dentist takes one X-ray and sees two copies of it. After this change the viewer shows one copy.

The cause is the capture hook, a function that runs each time a scanner sends an image. A rebuilt viewer list called the hook a second time for the same image. The hook now skips an image that it has already seen.

The checker ran on both files. This is the real output:

$ node scripts/check-text.ts testdata/readme/before.md
testdata/readme/before.md:1:1: hard no-example: the text has no example: add a closed code block, a line that starts with "Example" or "For example" and has content, or a Before and After pair of labels
1 findings (1 hard, 0 warn) for profile adjacent-engineer

$ node scripts/check-text.ts testdata/readme/after.md
0 findings (0 hard, 0 warn) for profile adjacent-engineer

The checker is shallow. It saw that the before text has no example. It did not see the jargon (Photon, ETag, rehydration). A different step finds jargon. That step uses a model.

How it works

The steps below run in order. They start with a reader that has no access to your repository and no hint of the topic.

  1. A cold reader reads your text. The cold reader is a read-only agent. It lists each word, step or jump where a stranger gets lost. These places are the stumbles. For each stumble it writes the question it would ask.
  2. Claude answers each stumble from your code, the linked issue or your docs. If no source backs an answer, the item goes on a list of open questions for you. Claude invents nothing.
  3. The rewrite opens with the gist. The gist is one sentence that says what the text is about.
  4. Next comes one example with real values.
  5. Last comes the mechanism. The mechanism is the part that explains how the thing works. Each term gets a short definition at its first use.

The cold reader also writes one sentence for what it thinks the text says. If that sentence differs from what you meant, the text fails. You can run only the cold reader with /greenhorn:test. It rewrites nothing.

How we got here

We started with a terms block at the top of the pull request description. Then we read the papers. In the one direct test (Rawson et al. 2015, with 131, 176 and 197 university students), performance was similar when examples came before or after the definition. So we dropped our own claim about order. What is left is a hypothesis that we are testing: a newcomer follows technical text better when a reader with no context marks where they get lost, when every gap is filled from the real source, and when the text opens with one concrete example. No study tests this combination.

What it cannot do

The reader is a model. It is not a human newcomer. It finds likely stumbles. It does not prove that a text is clear, and a clean result does not prove it either. The final test is a real person.

The method is a hypothesis. No study tests this combination, and the human eval has no results yet. The limits, such as 5 terms per text, are untested defaults. No study backs them.

The checker reads the shape of a text. It cannot tell whether a definition is true.

Install

  1. /plugin marketplace add gagoar/gago-plugins
  2. /plugin install greenhorn@gago-plugins

The two helper plugins, unmistakable and iceberg, install with greenhorn. If one is missing, /greenhorn:explain stops and prints the command to install it. The guide lists every command. The account of how we got here lists every source and what we could not read.

About the name

A greenhorn is a newcomer. The plugin is named for the reader it writes for.
